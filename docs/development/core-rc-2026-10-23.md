## Corrections from this audit

A fresh Composer security audit found `CVE-2026-108082` / `PKSA-xmwy-rmx5-m7h4` in both existing HttpFoundation lock entries (root 8.1.6, reference app 7.4.18). Compatible patched versions 8.1.9/7.4.21 were selected without changing dependency constraints. Both lockfiles subsequently passed the online audit. The reference app's local Core path reference was also refreshed to the current committed runtime. CI now checks both lockfiles explicitly. Benchmark provenance includes the full root lockfile hash and HttpFoundation version; measurements were repeated after patching.

The old benchmark lacked a native baseline and preloaded architecture analysis before measuring container build. The new default uses equivalent application behavior and fresh subprocesses; the old phase diagnostic is isolated behind `--phases`. It adds measured cold/cached build costs, warm boot, first HTTP, p50/p95 and memory without adding runtime features.

PHPStan 2.3.1 treated repeated calls to the lifecycle subprocess helper with identical arguments as pure, although source/cache state changes between calls. Its `@phpstan-impure` contract now describes those actual side effects; no errors were suppressed or runtime behavior weakened. Migration/release notes now cover aggregate exceptions, the reporting adapter/exit codes and mandatory production prebuild, rather than describing the whole release as only a rename.

## Limits and release gates

No reproduced local runtime, installation or architecture blocker remains. This is an RC verification result, not a published release or an exhaustive proof.

- Hosted CI on the exact final commit remains a release gate. It was not dispatched: the new changes are local, and no remote write was authorized. The workflow only triggers on main/dev pushes or manual dispatch; it does not provide a PR-required check. Branch protection must be assessed separately by the maintainer.
- Repository rename/remote URLs, package registration and recipe publication must be coordinated manually. Local simulated package/recipe installation does not prove public Packagist/Flex availability or target-repository/security-link availability. Confirm support/security endpoints and approve the release before manual tagging/publication.
- Only maintained Symfony 7.4/8.1 lines were rerun. Symfony 8.0 remains inside the declared compatible range but was not rerun; the existing CI excludes that historical line under its advisory policy. Composer security blocking was not disabled. Tested PHP versions are specific patches, not every allowed patch version.
- Production requires `APP_DEBUG=0`, isolated immutable release caches and successful build/warmup before traffic. Warm production requests intentionally trust built state; source edits under a running cache are not supported release validation. The adapter is necessary for reports around failed container boot.
- Benchmark limits: synthetic Modules-only chain, no database/Doctrine/Projects workload, no network/FPM/concurrency, CLI OPcache disabled, shared workstation and only three build repeats. See raw data and methodology; no general speedup is claimed.

The next authorized release preparation step is to review/commit this local RC diff. Push, repository rename, tag and publication each remain separate explicit actions.
