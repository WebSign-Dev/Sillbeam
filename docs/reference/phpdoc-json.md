# English PHPDoc JSON export

From the repository root, with development dependencies installed:

```bash
composer docs:export-json
```

The command writes **`build/docs/api/sillbeam-core.en.json`**. This is the only
public artifact created by the export. It is generated/ignored and is not committed.
Existing HTML is retained; `composer docs:build` continues to build HTML independently.
No translation, synchronization, website integration, push/release hook or deployment
is performed. The artifact is intended for manual translation and manual publication.

## Schema version 1

The normative [JSON Schema](phpdoc-api.schema.json) uses Draft 2020-12.
Breaking field/meaning changes require a new `schema_version`; readers should
validate the version before importing. This is a documentation format, separate
from architecture-report JSON and Doctor JSON.

```json
{
  "schema_version": 1,
  "package": "websign-dev/sillbeam-core",
  "version": "0.3.0",
  "language": "en",
  "elements": []
}
```

`package` comes from Composer metadata; `version` comes from the existing
`phpdoc.dist.xml` version number. `language` declares the project's English source
language; it does not translate or detect text language. No timestamps, absolute
source/cache paths, build IDs or HTML fragments generated by a renderer are added.

`elements` is a flat list sorted bytewise by fully qualified structural element
name (`id`). Container relationships retain the owning type's ID. IDs include the
leading backslash, for example:

- `\Sillbeam\Core\Module\ModuleRegistryInterface` — interface;
- `\Sillbeam\Core\Module\ModuleRegistryInterface::active()` — method;
- `\Sillbeam\Core\Architecture\ArchitectureReport::$data` — property;
- `\Example\Api::VERSION` — type constant, when present.

Supported kinds are `class`, `interface`, `trait`, `enum`, `enum_case`, `method`,
`function`, `property` and `constant`. Empty kinds are not fabricated. Each element
has `id`, `kind`, `name`, `container` (`null` for top-level elements), `summary`,
`description`, `tags` and `examples`. Missing prose is an empty string. Missing
optional values are `null`; absent optional fields do not imply a guessed contract.

| Element / field | Contents |
| --- | --- |
| Types | `extends`, `implements`, `traits`: sorted descriptor IDs; class `abstract`/`final` flags |
| Methods/functions | Original `signature`, ordered `parameters`, `returns`, ordered `throws`; method visibility and `abstract`/`final`/`static` flags |
| Parameters | Name, phpDocumentor `type`, plain `description`, default-expression text or null, by-reference/variadic flags |
| Returns / throws | Parsed type text or null and plain description |
| Properties | Visibility, parsed type, default-expression text or null |
| Constants / enum cases | Type where supplied by phpDocumentor, value-expression text or null |
| Tags | Name, description, optional type/variable/reference/link/version, in phpDocumentor order |
| Examples | Description, file/line metadata and `code` where provided; otherwise null metadata/code |

Parameter ordering is declaration ordering. Tag/exception/example ordering preserves
the descriptor order. A parameter can be addressed relative to its method ID and
name; types and members use phpDocumentor's own stable IDs. The exporter emits
own declarations, not copies of every inherited Symfony member. Type relationships
and inherited documentation already supplied by phpDocumentor remain available.
Virtual declarations described only through tags remain tags, not invented source
methods/properties.

## Text and code fidelity

`summary`, `description`, parameter/return/exception descriptions and tag descriptions
are text fields suitable for manual translation. Markdown, blank lines, fenced PHP
blocks and raw literal markup are retained as text. No `markdown`/HTML rendering
filter, HTML scraping, entity decoding or whitespace reflow is applied. Existing
inline PHPDoc references use phpDocumentor's textual representation.

`signature` retains the original declaration bytes, including names/aliases,
spacing, line breaks, defaults, attributes and inline comments. It excludes the
method body and whitespace immediately before its opening brace; abstract/interface
semicolons remain. Thus rich PHPDoc types do not overwrite the original native
signature. Parsed `type`/default fields are phpDocumentor's normalized/resolved
view, not a promise of the original spelling. phpDocumentor may supply defaults
such as `mixed` or inherited documentation; these are not newly authored prose.

Fenced examples remain verbatim inside descriptions. Typed example descriptors,
if supplied, also retain their `code`. **The stock phpDocumentor 3.10 factory can
represent `@example` as a generic tag**, without resolving its referenced file.
In that case the tag's text is retained and `code`/file metadata are null. The
exporter does not invent code, fetch files/URLs or add its own example resolver.
When a self-contained example is needed in the JSON, put a fenced code block in
the PHPDoc description. Current Core source contains no `@example` file tags.

UTF-8 Unicode, quotes, backslashes and control/line-break characters are encoded
with PHP's JSON encoder. Invalid UTF-8 and malformed/incomplete intermediate data
fail the command rather than produce partial JSON. Do not translate IDs, types,
signatures, expression strings, relationship fields or PHP code while translating
prose manually. The exporter itself has no translation logic.

## Tooling and public boundary

The export uses the existing distribution config and phpDocumentor 3.10's
[custom Twig transformations](https://docs.phpdoc.org/guide/features/theming/extending-a-template.html).
The [Twig descriptor context](https://docs.phpdoc.org/guide/guides/templates/twig.html)
is projected by the minimal template in `tools/phpdoc-json/`. It does not extend
or run the HTML template. Only phpDocumentor analyzes PHP: there is no second AST
parser or runtime reflection/autoloading of application declarations.

The existing visibility policy is retained: public/protected members of
non-internal types, excluding `@internal` types/members and private members.
Supported Core types remain marked `@api`. See [public API](public-api.md).
Changing that boundary requires the same review as the HTML reference.

The export asks phpDocumentor to retain source in its separate
`.phpdoc/json-cache/`. Existing descriptor byte positions and source supply original
signatures; a small PHP tokenizer only locates body delimiters inside those known
spans. It does not discover API elements or build another AST. Staged descriptors
and whole-file source are removed after each attempt and never enter the final
public JSON. Only the final JSON file is atomically replaced after encoding succeeds.
A failed build preserves the previous successful artifact and returns nonzero;
callers must check the exit code rather than assume an old artifact is current.

phpDocumentor's cache and this template are version-sensitive. Tests target 3.10.0;
review the descriptor/offset contract when upgrading it. The separate cache can
be removed to force fresh analysis. This is a development-only tool: no new runtime
or development dependency, runtime autoloader mapping, CI trigger or deployment
process is added. Automated tests export only into temporary fixture projects.
