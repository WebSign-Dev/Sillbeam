# Sillbeam Core v0.2.0 — unreleased

This version prepares the technical rename to `websign-dev/sillbeam-core`, repository target `WebSign-Dev/sillbeam-core`, PHP namespace `Sillbeam\Core\`, bundle `SillbeamCoreBundle` and extension `SillbeamCoreExtension`.

These are breaking Composer and PHP API changes. Follow the [upgrade guide](../migration/0.2.0.md) before updating an application. The Symfony extension explicitly retains the `sillbeam` alias; configuration, CLI, routing type and named service IDs remain stable. All existing Module, Project, routing, service and Doctrine features are retained.

PHP, Symfony and Doctrine requirements are unchanged. No Frame or Components work is included. The Flex recipe is prepared locally at `flex-recipe/websign-dev/sillbeam-core/0.2`. No repository rename, publication or release tag has been performed.

Architecture validation now collects independent existing rule violations in a shared structured result and distinguishes fatal analysis failures. Invalid architectures still block container builds. See [architecture analysis](../reference/architecture-analysis.md) for the API and exception behavior; existing CLI names remain unchanged; output now includes available locations and remediation hints.

The existing architecture command now supports versioned JSON and consistent exit codes. Opt in to container-independent reporting with the Console Application import described in [CLI setup](../reference/cli.md); normal container validation stays strict.

Development compilation reports detailed findings. Non-debug production HTTP reuses a prebuilt container and refuses cold compilation with generic 503. CLI container compilation and cache clear/warmup remain strict; build commands recheck current sources even with a cached container. Deploy with an isolated release cache and stop on nonzero validation/build exits. This is an operational breaking change; see the upgrade guide.

The [integrated RC report](../development/core-rc-2026-10-23.md) records the tested combinations, remaining release gates and reproducible native-Symfony comparison. Measurements describe synthetic workloads and do not establish a general performance advantage.
